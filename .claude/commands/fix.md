# /fix — Структурований баг-фікс (виправлення помилки)

Аргумент: опис або ID бага. Приклад: `/fix кошик не оновлює суму` або `/fix B-07`.

## Крок 1 — Історія
Прочитай `docs/BUGS.md` і `Grep`-ом тему в `docs/SESSION_STATE.md`.
Що вже пробували? **Не повторюй того, що вже не спрацювало.**

## Крок 2 — Читай код
Знайди і **реально відкрий** файли з проблемою. Не з памʼяті.
Якщо можливо — відтвори баг (тест / лог / браузер через `/qa-explore`) **до** фіксу, щоб було чим довести, що виправлено.

## Крок 3 — Поясни ЧОМУ (до будь-якої зміни)
Напиши Вові, простими словами, з поясненням термінів:
- **Де** проблема (файл:рядок).
- **Чому** виникає — корінь, не симптом.
- **Межі** — де ще живе та сама помилка (той самий патерн в інших місцях).
- **Що** зміниш і чому це вирішить.
- **Ризик** — що може зачепити.

**Чекай «Роби».**

## Крок 4 — Фікс
Тільки те, що описав у Кроці 3. Навколо нічого не «покращувати».
Дві невдалі спроби поспіль → зупинись, переглянь гіпотезу, не латка-на-латку.

## Крок 5 — Перевірка
```
npx tsc --noEmit
npm test
```
- Сценарій із Кроку 2 більше не ламається.
- Попередні фікси в цьому місці збережені.
- Якщо можна — додай тест, що ловить цей баг (регресійний — щоб не повернувся).
🔴 «Виправлено ✓» — лише після exit 0 / підтвердженого відтворення.

## Крок 6 — BUGS.md
Перемісти баг з «Відкриті» в «Закриті»: дата + корінь + як виправлено. Рядок у журнал сесії.

## Крок 7 — Результат
Вові: що змінено, чому тепер працює, як перевірити самому (на телефоні — конкретні кроки).
