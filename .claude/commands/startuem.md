## Крок 0 — Гілка і свіжий стан (ПЕРШИМ, автоматично)

1. **Гілка.** Сесія стартує на авто-гілці `claude/startuem-<хеш>` — на ній і працюй. Під конкретну задачу можна `vova/<тема>`.
   Потік: робоча гілка → `/finish` (PR — pull request, запит на злиття → squash — злиття одним комітом) → `main` → автодеплой.
   🛑 **У `main` напряму не пушимо** (виняток — дрібні docs-коміти, якщо Вова дозволив).
2. **Свіжий стан:**
   ```
   git fetch origin
   git pull origin main
   git log --oneline -15
   ```
   🔴 **Стан читай з `origin/main`, а не з файлів на диску.** Локальна копія може стояти на старій гілці — документи виглядатимуть свіжими, а будуть учорашні. Звірка:
   ```
   git log --oneline origin/main ^HEAD     # є на GitHub, нема в мене
   git log --oneline HEAD ^origin/main     # є в мене, НЕ доїхало на GitHub (має бути порожньо або у відкритому PR)
   ```
   Якщо `git pull` дав конфлікт — **не розводь наосліп**, доповідай Вові: майже завжди це означає, що гілка застаріла і робота вже пішла в `main` іншим шляхом.
3. 🔴 **Живий журнал сесії.** Створи `docs/_session-log/<РРРР-ММ-ДД>.md` (тека одна!). **Дописуй після кожної значущої дії:** файл/функція · навіщо · що не спрацювало · слова Вови дослівно · PR# / деплой#. **Комітуй і пушай кожні кілька кроків** — журнал, якого нема в git, для наступного чату не існує.

## Крок 1 — Обов'язкове читання (має вміщатися у вікно!)

> 🔴 **Чому список короткий.** У проєкті-джерелі обовʼязкове читання розрослося до 8 файлів ≈ 407 тис. токенів при вікні 200 тис. (204%). Інструкція була фізично невиконанна: чат читав верхівки й тихо губив решту. Тримай **разом ≤15% вікна**; не додавай сюди важкі файли.

Прочитай **повністю**, у такому порядку:

1. **`docs/NOW.md`** — 🔴 **ПУЛЬС, ЧИТАЙ ПЕРШИМ.** Де стоїмо ЗАРАЗ: що зроблено в останній сесії, що не доробили, що спитати у Вови, що далі, чого не чіпати.
2. `docs/HOT_RULES.md` — правила, що порушуються найчастіше.
3. `docs/BUGS.md` — відомі баги.
4. `docs/NEVYKONANI_ZAVDANNIA.md` — **єдиний реєстр усього незробленого** (замовлення власника, технічна черга, питання що чекають рішення).
5. `docs/VOVA_PROFILE.md` — як Вова комунікує і працює.

Плюс git:
```
git log --oneline -10
git branch --show-current
```

### Решта — СИТУАТИВНО, і ніколи цілком
Літопис (`SESSION_STATE.md`), повна карта (`docs/CLAUDE.md`), архітектура, плани — **тільки `Grep` за темою**, коли тема справді виникла. Правило: спершу `NOW.md`, і лише якщо чогось бракує — точковий пошук. «Прочитаю все, раптом знадобиться» зʼїдає вікно до того, як почнеться робота.

## Нагадування на всю сесію
- **Пояснення англійських термінів у дужках** — у кожному повідомленні.
- **Короткі повідомлення**, одна думка за раз (Вова часто з телефона).
- **Сперечайся чесно**, не погоджуйся заради ввічливості. Пропонуй найкраще для проєкту, а не лише те, що вже є в коді.
- **Звертання до власника — чоловічий рід** («ти зробив»), про себе теж («я перевірив»).
- 🔴 **Не пиши ✓ / «готово» / «тести зелені», поки не побачив exit 0 (код успішного завершення) у виводі команди.**
- **Двогілковий потік:** гілка → `/finish` → `main`. Передача в новий чат — `/onovy`.
