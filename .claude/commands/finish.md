1. Переконайся, що `docs/_session-log/<РРРР-ММ-ДД>.md` існує і містить усі значущі дії. Нема / відстає — допиши **зараз**.
2. Кожен запис: **що** (файл/функція) · **навіщо** · **що пробував і що НЕ спрацювало** · **слова Вови дослівно** · інцидент і як виправив · PR# · деплой#.
3. Підсумок (Крок 8) генеруй **з журналу**, не з памʼяті — у великій сесії контекст губиться.

## Крок 1 — Час
`date` — запамʼятай (для версії і журналу). Не вигадувати.

## Крок 2 — Підняти версію: CACHE_NAME у public/sw.js
Якщо проєкт має маркер версії / кешу (напр. назва кешу в service worker — фоновому скрипті PWA) — підніми за форматом проєкту з часом із Кроку 1.
**Виняток:** змінювались **тільки** `.md` або `.claude/` — не чіпати. Нема такого маркера — крок пропускається.

🔴 **Не пиши ✓, поки не побачив exit 0.** Червоне — СТОП, виправити, тоді далі.

## Крок 5 — Яка гілка?
`git branch --show-current` → `main`: Крок 6А · інша: Крок 6Б.

## Крок 6А — Уже на main (рідко)
```
git add <конкретні файли>            # НЕ "git add ." наосліп
git commit -m "<що зроблено>"
git push -u origin main
```

## Крок 6Б — Гілка → PR → squash

### 6Б.0 — Підтягнути свіжий main (проти конфліктів і затирання)
```
git fetch origin main
git merge origin/main --no-edit       # конфлікти — ВРУЧНУ, ніколи -X theirs наосліп
npm run build && npm test         # після злиття код валідний
```

### 6Б.1 — Коміт і пуш гілки
```
git add <конкретні файли>
git commit -m "<що зроблено>"
git push -u origin <поточна-гілка>
```
Мережева помилка — до 4 повторів із паузами 2/4/8/16 с.

### 6Б.2 — PR
GitHub MCP `create_pull_request`: owner `Volodymyr221`, repo `LikarskyTravy-Market`, base `main`, head `<гілка>`, title — коротко, body — маркований список змін. Запамʼятай номер.

### 6Б.3 — Злиття
`merge_pull_request`: `pullNumber` з 6Б.2, `merge_method: squash`. Після злиття стартує GitHub Actions → GitHub Pages.

## Крок 7 — Перевірка деплою
Через кілька хвилин перевір лічильник версії `v{N} · DD.MM HH:MM` у футері сайту на https://volodymyr221.github.io/LikarskyTravy-Market/ і статус GitHub Actions (CI — автоматичні тести й деплой).
Деплой не стартував — ретригер (повторний запуск):
```
git checkout main && git pull origin main
git commit --allow-empty -m "ci: retrigger" && git push origin main
git checkout <робоча-гілка>
```
🔴 «Задеплоєно» — лише коли побачив зелений run / нову версію на сайті.
