# /onovy — Онови документацію для переходу в новий чат / на інший акаунт

> **Мета одна:** після цієї команди в репозиторії не лишається нічого, чого не побачить наступний чат.
> 🔑 **`/onovy` = «передай наступному». `/finish` = «опублікуй на сайті».** Різні дії: можна передати незадеплоєне і задеплоїти без передачі.
**Без аргументів.**

---

## Навіщо
У проєкті-джерелі «інший акаунт не розумів, що вже зроблено». Git **не відставав** — відставали **документи**: три копії «поточного стану» з різними датами, план потоку зі статусом «чекаю» для вже задеплоєного, ненаписаний журнал. Ця команда — від цього.

---

## Крок 1 — Час і місце
```
date
git branch --show-current
git fetch origin
git status --short
```
🔴 Стан читай з `origin`, не з диска.

## Крок 2 — Дописати журнал сесії
`docs/_session-log/<РРРР-ММ-ДД>.md`. Нема — **створи зараз** і запиши все із сесії.
Кожен запис: що (файл/функція) · навіщо · що НЕ спрацювало · слова Вови дослівно · інцидент · PR# · деплой#.

## Крок 3 — Пульс `docs/NOW.md`
(Якщо є скрипт, що генерує авто-блок із git — гілка, останній коміт, останній PR, що не в `main` — запусти його першим.)
Руками переписати:
- 🎯 **ЗАРАЗ** — один абзац;
- ✅ **ЗРОБЛЕНО В ЦІЙ СЕСІЇ** — з журналу, з PR / деплоями;
- 🚧 **НЕ ДОРОБЛЕНО** — **обовʼязково з причиною**;
- ❓ **ВІДКРИТІ ПИТАННЯ ДО ВОВИ**;
- ➡️ **ДАЛІ** — черга (звірити з `NEVYKONANI_ZAVDANNIA.md`);
- 🛑 **НЕ ЧІПАТИ** — крихкі місця.

🛑 Жодної заглушки. Порожній розділ гірший за відсутній.

## Крок 4 — Літопис і плани
1. `docs/SESSION_STATE.md` — новий запис угорі.
2. `docs/BYYOU_PLAN.md` — 🔴 **чесний статус:**
   - потік завершено → `Статус: done`, файл в `_archive/`, живий — у шаблон;
   - не доробили → `Статус: paused` + дозаповнити «Де зупинились».
   Обидва знімають `active` і тим відмикають замок пушу (хук `byyou-push-lock.js`). `active` посеред передачі не буває.
3. Закрито / зʼявилось нове → `NEVYKONANI_ZAVDANNIA.md`, `BUGS.md`.

## Крок 5 — Перевірити
Змінювався код:
```
npx tsc --noEmit
npm test
```
Є сторожі документації (перевірка свіжості NOW.md, битих посилань) — прожени.
🔴 Червоне — **виправити, не передавати**: передана поломка гірша за непередану роботу. Не пиши «зелене» без exit 0.

## Крок 6 — Закомітити ВСЕ
```
git add -A
git commit -m "docs: передача в новий чат — <дата>"
git status --short     # має бути ПОРОЖНЬО
```
🔴 **Незакомічене = втрачене.** Контейнер сесії тимчасовий.
Якщо пульс генерується з git — після коміту онови його ще раз і долий коміт, інакше він опише стан «до останнього коміту».

## Крок 7 — Запушити
```
git push -u origin <поточна-гілка>
```
Мережева помилка — до 4 повторів (2/4/8/16 с).

## Крок 8 — 🔴 Розвилка: зливати в main?
```
git diff --stat origin/main..HEAD -- src/ public/ next.config.* package.json
```
- **Порожньо** (лише документи) → злий сам: PR + squash. Сайт не зміниться, наступний чат побачить усе в `main`.
- **Не порожньо** (є код) → 🛑 **СТОП.** Злиття = деплой на живий сайт. Скажи:
  > «На гілці є код: `<файли>`. Злиття = деплой. Документацію запушив — видно на гілці `<назва>`. Кажи «деплой», якщо публікуємо, або лишаю на гілці.»

## Крок 9 — Звіт: що НЕ доробили (голосно)
```
📦 ПЕРЕДАЧА ГОТОВА — <дата, час>
Гілка: <назва> · у main: <так / ні, чекає «деплой»>
NOW.md оновлено · журнал дописано · перевірки зелені (exit 0)

✅ Зроблено: <з PR/деплоями>
🚧 НЕ доробили: <з причинами>
❓ Чекаю відповіді: <питання>
➡️ Наступний крок: <…>
```

| мета | передати наступному чату | опублікувати на сайті |
| `NOW.md` | головний результат | оновлює |
| злиття в main | лише якщо самі документи | завжди |
