# /fullaudit — Незалежний повний аудит УСЬОГО застосунку

> Не плутати з `/audit` (легкий чекліст по diff). Тут — весь застосунок, незалежні агенти, adversarial-верифікація (кожну знахідку намагаються спростувати). **Лише ЗНАХОДИТЬ, не виправляє.**

## Принципи
1. **Незалежність:** субагентам НЕ передавати історію сесії («ми щойно зробили X»). Тільки хартію (опис зони перевірки) + карту коду.
2. **Adversarial-верифікація:** кожна знахідка — 3 спростувачі з різними лінзами.
3. **Весь застосунок**, не diff.
4. І пошук, і верифікація — високе зусилля (high effort). Слабкий спростувач — така ж вада, як фальшива знахідка.

## Крок 0 — SCOUT (розвідка)
Glob / `wc -l` → карта: усі теки коду, конфіги, міграції БД, серверні функції, CI-workflow, дані. Передати у Workflow як `args.map`.

## Крок 1 — Workflow: FIND → VERIFY (конвеєр)
**Виміри** (кожен сканує ВЕСЬ застосунок):
correctness (логіка, гонки, граничні випадки) · security (XSS, injection, секрети, права доступу / RLS, довіра клієнту) · payments (суми рахує сервер, ідемпотентність — повторний запит не списує вдруге, вебхуки) · data (схема vs запити, дублі, міграції) · performance (N+1 запити, пагінація, важкі зображення) · deadcode (мертвий код, дублі) · architecture (дрейф патернів, циклічні залежності) · silentfail (тихі відмови) · build (збірка vs джерело) · pwa_cache (якщо є) · mobile (iOS/Android-крихкість) · i18n_legal (за потреби: склад, протипоказання, обовʼязкові тексти).

**Знахідка** (schema — структура відповіді): `{title, file, line, severity: critical|high|medium|low, scenario: "вхід/стан → що ламається", evidence}`. Без конкретного сценарію — не знахідка. Плюс `coverageNote`: що НЕ вдалось перевірити.

**Лінзи спростувачів:**
- *reachable* — чи шлях коду реально досяжний?
- *guarded* — чи вже є захист поруч?
- *reproduces* — прогнати сценарій по реальному коду: справді ламається?

**Вердикт:** `{real, confidence, reasoning}`. ≥2/3 real → **confirmed**; рівно 1/3 real з high confidence і конкретним поясненням → **second-look**; інакше → **refuted**.

Скрипт: `pipeline(DIMENSIONS, d => agent(auditPrompt(d), {schema: FINDINGS, effort:'high'}), ({d,r}) => parallel(r.findings.map(f => () => parallel(LENSES.map(l => () => agent(refutePrompt(f,l), {schema: VERDICT, effort:'high'}))).then(classify))))` → повертає `{confirmed, secondLook, refuted, coverage, failedDims}`.

## Крок 2 — Звіт
1. 🔴 **ПІДТВЕРДЖЕНІ** — за severity: `[sev] заголовок · file:line · сценарій · вимір`.
2. 🟡 **ВАРТЕ ДРУГОГО ПОГЛЯДУ** — + чому спростувачі розійшлись.
3. ⚪ **СПРОСТОВАНІ** — лише кількість.
4. 📊 Таблиця по вимірах: знайдено / підтверджено / second-look / спростовано.
5. 🚫 **ЩО НЕ ПЕРЕВІРЕНО** — coverage + failedDims + обмеження середовища. **Обовʼязково; мовчазне «все чисто» заборонено.**

Після звіту — спитати Вову, що робити зі знахідками.
